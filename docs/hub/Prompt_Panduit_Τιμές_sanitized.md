# Prompt / Προδιαγραφή — Μηχανή Τιμολόγησης Panduit (sanitized)

Αυτό είναι το είδος προδιαγραφής που δόθηκε στο AI για να χτίσει το εργαλείο «Αυτόματη Ενημέρωση Τιμοκαταλόγου Panduit». Τα πραγματικά ποσοστά έκπτωσης, ονόματα πελατών και εσωτερικά αρχεία έχουν αντικατασταθεί με γενικά παραδείγματα — δείχνει τη **δομή** του prompt, όχι τα εμπιστευτικά δεδομένα πίσω του.

## Στόχος

Ένα αυτόνομο HTML εργαλείο, χωρίς server, που παίρνει το μηνιαίο export τιμών, έναν κατάλογο προμηθευτή και ένα αρχείο ειδικών τιμών πελατών, και επιστρέφει το ίδιο export στην ίδια ακριβώς μορφή — αλλαγμένο μόνο στις στήλες τιμής και έκπτωσης.

## Κανόνες προτεραιότητας (ζητήθηκε ρητή ιεραρχία, όχι «καλύτερη προσπάθεια»)

1. Καταργημένοι/επιβεβαιωμένοι κωδικοί και χειροκίνητες εξαιρέσεις πρώτα — υπερισχύουν των πάντων.
2. Ειδική συμφωνία-ομπρέλα («Πελάτης-τύπος Α») → αυτή η τιμή, πάνω από όλα τα άλλα.
3. Συγκεκριμένη κατηγορία προϊόντος (πχ εξαρτήματα σύνδεσης) → πάντα τιμή καταλόγου, ποτέ ειδική τιμή πελάτη, ανεξαρτήτως αν υπάρχει καταχωρημένη.
4. Άλλη κατηγορία με δύο μεταβλητές (χρώμα, μήκος) → κανόνας ανά συνδυασμό.
5. Ό,τι έχει καταχωρημένη ειδική τιμή πελάτη τη χρησιμοποιεί, εκτός αν πιάστηκε από προηγούμενο κανόνα.
6. Χωρίς καμία πηγή → κράτησε την παλιά τιμή, μην επινοήσεις τίποτα.

**Μάθημα από την υλοποίηση:** ο κανόνας 3 δούλευε μόνο για μία ακριβή διατύπωση της περιγραφής. Ο πληθυντικός και μια δεύτερη ισοδύναμη λέξη ξέφευγαν από τον κανόνα και έπεφταν στον κανόνα 5, παίρνοντας τυχαία τη φτηνότερη ειδική τιμή κάποιου πελάτη αντί για την τιμή καταλόγου. Η διόρθωση ήταν να ζητηθεί από το AI να ελέγξει **ρίζα λέξης**, όχι ακριβή φράση, και να επαληθευτεί σε όλο το dataset ότι δεν πιάνει ψευδώς άσχετες γραμμές πριν εφαρμοστεί.

## Επιλογή τιμής όταν υπάρχουν πολλές ειδικές τιμές πελατών για τον ίδιο κωδικό

- Μία τιμή στο αρχείο → αυτή.
- Δύο τιμές → η μεγαλύτερη (πιο συντηρητική επιλογή).
- Τρεις ή περισσότερες → η δεύτερη μεγαλύτερη (αγνοεί το ακραίο outlier).
- Ζητήθηκε ρητά: ένας συγκεκριμένος πελάτης να εξαιρείται πάντα από αυτόν τον υπολογισμό (test/εσωτερικός λογαριασμός, όχι πραγματική πώληση).

## Δικλείδες ασφαλείας (μη-διαπραγματεύσιμες)

- Αν η νέα καθαρή τιμή αποκλίνει πάνω από ένα όριο (πολλαπλάσιο X ή κλάσμα 1/X του παλιού), **μην τη γράψεις** — κράτησε την παλιά και σημείωσέ τη για ανθρώπινο έλεγχο, με τις υποψήφιες τιμές δίπλα-δίπλα.
- Μετά από κάθε εγγραφή, ξαναδιάβασε ολόκληρο το αρχείο και επιβεβαίωσε ότι άλλαξαν ΜΟΝΟ τα δύο αναμενόμενα κελιά ανά γραμμή — καμία μορφοποίηση, στήλη ή φύλλο δεν πειράζεται.
- Ενσωμάτωσε ένα μικρό σύνολο test με γνωστές, χειροκίνητα επαληθευμένες τιμές, να τρέχει σε κάθε εκτέλεση και να εμφανίζεται στο αποτέλεσμα.

## Τι έμαθε η διαδικασία (αξίζει να το ξέρει όποιος γράφει παρόμοιο prompt)

- Ζήτα από το AI να **σου δείξει τα δεδομένα**, όχι μόνο τον κώδικα: ένα audit που συγκρίνει παλιά/νέα τιμή σε όλο το dataset αποκάλυψε ένα πραγματικό λάθος λογικής που κανένα unit test δεν θα έπιανε, γιατί το test κάλυπτε μόνο τους ήδη γνωστούς κωδικούς.
- Όταν κάτι «δουλεύει σε όλο το δείγμα», έλεγξε αν δουλεύει **για τον σωστό λόγο** ή επειδή μια σύμπτωση (πχ ένας μόνος πελάτης-πηγή) κάλυψε ένα βαθύτερο πρόβλημα κατηγοριοποίησης.
- Κράτα τις παραμέτρους (εξαιρέσεις, όρια, ρυθμίσεις) έξω από τον κώδικα, σε ξεχωριστό αρχείο δεδομένων· έτσι μια αλλαγή πολιτικής δεν απαιτεί νέα έκδοση του εργαλείου.
